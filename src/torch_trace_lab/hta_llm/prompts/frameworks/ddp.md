The context table shows `parallelism = DDP` (PyTorch DistributedDataParallel). Use this when reading the communication evidence and choosing DDP fixes:

- **Reading the all-reduce numbers.** DDP all-reduces gradients in buckets during the backward pass, so all-reduce overlaps compute by design; only the exposed part adds to the step. NCCL kernel time includes waiting for the slowest rank to join the collective. On a rank that waits for a straggler, all-reduce and exposed all-reduce time are mostly that wait, not the cost of moving gradients: read them together with RANK_STRAGGLER and the rank comparison. The lowest all-reduce time across ranks (the "Communication by collective" table) is the best estimate of the transfer cost the bundle offers, but only an upper bound: even the fastest rank may wait briefly for the others, so call it "at most" that cost, never the exact or true transfer cost. Fix a straggler before tuning communication.
- **Broadcast every step.** With `broadcast_buffers=True` (the default), DDP broadcasts the model's buffers (e.g. BatchNorm running statistics) from rank 0 at every forward pass; it shows up as broadcast time in the "Communication by collective" table. If the buffers don't need to be identical on every rank, or the model uses SyncBatchNorm, `DistributedDataParallel(..., broadcast_buffers=False)` removes it.
- **Several nodes.** When `num_nodes` is greater than 1, all-reduce crosses the network between nodes (e.g. InfiniBand), which is much slower than NVLink within a node, so exposed all-reduce matters more. Fewer, larger all-reduces per step (gradient accumulation with `no_sync`, larger buckets) help most there.

DDP settings that change communication (the `[ddp]` table of `--meta` records them):

- **`bucket_cap_mb`** (default 25): gradients are all-reduced in buckets of this size. Larger buckets mean fewer, more efficient all-reduce calls; smaller buckets let communication start earlier in the backward pass and overlap more. Try larger buckets when exposed all-reduce is high on the fastest rank, especially across nodes.
- **`gradient_as_bucket_view=True`**: gradients become views into the all-reduce buckets, which saves a copy of every gradient after each all-reduce and the memory for it.
- **`no_sync()` with gradient accumulation**: wrap all but the last micro-batch of each accumulation step in `model.no_sync()`, so gradients are all-reduced once per optimizer step instead of after every micro-batch.
- **`static_graph=True`**: when the set of parameters that get gradients is the same every iteration, this lets DDP skip per-iteration bookkeeping and reorder buckets to match the real gradient order.
- **`find_unused_parameters=True`** adds a traversal of the autograd graph every iteration; keep it `False` unless the model really has parameters that get no gradient.
